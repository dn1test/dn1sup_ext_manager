# Changelog (Лог изменений)

Лог изменений **DN1Sup Extension Store** (`dn1sup_ext_manager`).
Формат версий соответствует правилам `MAJOR.MINOR.PATCH`.

Изменения остальных расширений DN1Sup документируются в их собственных
репозиториях (`dn1test/dn1sup_*`); этот репозиторий хранит только реестр
каталога (`registry.json`: id/name/repo), необходимый для установки и обновлений.

## [0.10.2] — 2026-10-09

### DN1Sup Extension Store (v0.10.2)
- **Логи правок для репозиториев без «v»-префикса тегов**: полный тег для
  compare API теперь берётся из списка релизов (находится по версии без
  префикса), фолбэк — `v<version>`. Раньше `v` дописывался вслепую —
  репозиторий с тегами вида `0.10.0` получал 404 от compare и блок «изменения»
  молча не появлялся.
- **Пагинация автопоиска**: `repos_of_owner` читает до 5 страниц по 100
  репозиториев — при большем количестве хвост молча терялся (общий файл
  `dn1sup_updater.rb` синхронизирован во все расширения).
- `release_newer_than_install?`: срез префикса тега регистронезависим
  (`/\Av/i`) — тег `V1.2.3` больше не ломает монорепо-защиту.
- **Снапшот**: файл формата новее поддерживаемого (`version > 4`) игнорируется
  при загрузке — прежние поля в будущем формате могут иметь другой смысл.
- **Сетевой фолбэк реестра** (когда `data/registry.json` отсутствует):
  запрос выполняется один раз за сессию — раньше каждый рендер каталога
  блокировал UI таймаутами (4 c connect + 6 c read).
- Тесты: `IDYES = 6` (реальное значение SketchUp API; мок возвращал 2),
  регрессия на `full_tag_name`.

## [0.10.1] — 2026-10-09

### DN1Sup Extension Store (v0.10.1)
- **Безопасность удаления**: `perform_uninstall` принимает только id вида
  `dn1sup_[a-z0-9_]+` из каталога (реестр + найденные). Раньше id из диалога
  уходил в `FileUtils.rm_rf` без проверки — значение `"."` удалило бы всю
  папку Plugins, `".."` — каталог SketchUp.
- При удалении сбрасывается и `installed_at_<id>`: раньше метка времени
  переживала удаление, и после переустановки старой сборки даты сравнивались
  с прошлой установкой (возможен ложный статус «Смена версии»).
- **Ротация логов на Windows**: перед `File.rename(*.rbz.log, *.old)`
  существующий `.old` удаляется. Раньше rename падал `Errno::EEXIST`, ошибка
  глоталась — и после первого переполнения лога (1 МБ) при существующем `.old`
  запись логов прекращалась навсегда (общий файл `dn1sup_updater.rb`
  синхронизируется во все расширения).
- **Иконки PNG починены**: IHDR-чанк собирался как 20 байт вместо 13
  (`pack('N5')` вместо `pack('N2C5')`) — все `store_16/24/32.png` были
  нечитаемыми декодерами. Иконки перегенерированы.
- Выбор SVG-иконки тулбара теперь требует SketchUp **2020.1+**
  (`version.to_f >= 20.1`): раньше `to_i >= 20` пропускал 2020.0, где SVG в
  тулбарах ещё не поддерживается, и при битых PNG иконка была сломана.
- **Сборка .rbz без системного zip** (rubyzip-fallback в `tools/pack.rb`):
  glob стадии нормализован в прямые слэши (обратные трактуются как escape —
  архив собирался пустым), добавлена проверка полноты стадии и минимального
  размера архива.

## [0.10.0] — 2026-10-09

### DN1Sup Extension Store (v0.10.0)
- **Удалённые и переименованные репозитории убираются из каталога.** Перед
  загрузкой релизов каждый репозиторий записей (реестр + найденные) проверяется
  запросом `GET /repos/{owner}/{repo}` (не чаще раза в сутки, кнопка
  «Обновить» — всегда): HTTP 404 — репозиторий удалён, редирект на другое
  `full_name` — переименован.
- **Неустановленные** расширения с мёртвым репозиторием исчезают из всех
  вкладок каталога, включая «Обновления». **Установленные** остаются с нейтральной
  пометкой «Репозиторий недоступен»/«Репозиторий перемещён» — без кнопок
  установки/обновления (переустановка отклоняется и на стороне Ruby); удалить
  такое расширение можно через Store.
- Кэши релизов/коммитов мёртвого репозитория чистятся, найденные ранее записи
  по нему удаляются; релизы по старому имени не запрашиваются (редирект
  переименования иначе вернул бы релизы нового репозитория под старым именем —
  ложное «обновление»).
- **Самовосстановление**: если репозиторий пересоздан под тем же именем,
  пометка снимается при следующей проверке, и карточка возвращается. При
  обнаружении переименования автопоиск нового репозитория `dn1sup_*` выполняется
  немедленно (не дожидаясь суточного скана), и его релизы подтягиваются сразу.
- Сетевая недоступность (таймаут, лимиты API) статус не меняет — пометки
  «мёртвый» ставятся только по однозначному ответу GitHub (404/redirect).
- Снапшот каталога поднят до **v4**: статусы репозиториев (`stale`) переживают
  перезапуск; старые форматы v1–v3 читаются, поле игнорируется старыми версиями.
- `Dn1sup::Updater`: новый метод `repo_meta(repo)` → `{exists:, repo:, renamed:}`
  / `{exists: false}` / `nil` (общий файл синхронизирован во все расширения).

## [0.9.0] — 2026-10-09

### DN1Sup Extension Store (v0.9.0)
- **Обновления распознаются и по дате публикации релиза, а не только по номеру
  версии.** Если релиз издан позже установленной сборки (переизпуск без бампа
  версии, исправление под тем же номером), самопроверка обновлений предлагает
  установку с формулировкой «опубликована обновлённая сборка версии X (ваша
  установлена раньше)».
- **Дата установки**: при каждой установке/обновлении через Store и апдейтер
  пишется pref `installed_at_<id>`; для вручную установленных расширений дата
  неизвестна — работает прежнее поведение (только номера версий).
- Каталог: статус «Смена версии» теперь ставится и когда релиз установленной
  версии отсутствует в списке (старая установка, снапшот хранит лишь 10
  релизов) — по дате установки, и при переизпуске того же номера позже даты
  установки (кнопка «Установить» на карточке).
- Защита от ложных срабатываний в монорепо: дата релиза сравнивается с датой
  установки, только когда релиз относится к этому расширению (версия из
  registry.json совпадает с тегом релиза либо реестр недоступен).
- `Dn1sup::Updater`: `fetch_latest` возвращает источник версии (`from_registry`),
  новые методы `installed_at`/`mark_installed`, `install_from_url` принимает
  `id:` (общий файл синхронизирован во все расширения — дата-фолбэк появится
  в каждом из них со следующим релизом).

## [0.8.0] — 2026-10-09

### DN1Sup Extension Store (v0.8.0)
- **Автопоиск расширений на GitHub**: менеджер сканирует репозитории `dn1sup_*`
  аккаунта `dn1test` (`GET /users/{owner}/repos`, фолбэк `/orgs/`) — расширения,
  которых нет в registry.json, появляются в каталоге с бейджем «Найдено» и
  кнопкой установки. Метаданные — из `registry.json` самого репозитория
  расширения, фолбэк — описание с GitHub. Скан выполняется раз в сутки и по
  кнопке «Обновить»; найденное без стабильного `.rbz`-релиза не показывается.
- **Скрытие найденного**: кнопка на карточке скрывает расширение из каталога
  (pref `hidden_repos`); возврат — пункт меню «Показать скрытые расширения».
- **Логи правок**: для продуктов с обновлением/сменой версии подтягиваются
  коммиты между установленной и предлагаемой версиями (`GET /compare`,
  до 15 сообщений) — блок «Изменения» в «Что нового».
- Установка/переименование работают и для найденных расширений
  (`find_entry` ищет и в реестре, и среди найденного).
- Снапшот релизов переведён на формат v3 (+ найденные расширения и коммиты;
  чтение v2/v1 сохраняется) — каталог с найденным виден офлайн.
- `Dn1sup::Updater`: новые методы `repos_of_owner` и `compare_commits`
  (общий файл синхронизирован во все расширения).

### Расширения (развязка с менеджером)
- Все расширения `dn1test/dn1sup_*` теперь **самостоятельны**: у каждого —
  самообновление через собственный GitHub-релиз (фоновая проверка раз в сутки
  + меню «Проверить обновления сейчас»), корневой `registry.json` с
  метаданными для автопоиска, свежий общий `dn1sup_updater.rb`.
- `dn1sup_autoselect_tag` 0.4.1, `dn1sup_save_settings` 0.12.1: исправлен
  `REPO` самообновления (указывал на старый монорепозиторий).
- `dn1sup_time_project2` 0.5.0, `dn1sup_create_project` 0.4.0,
  `dn1sup_comp_add_view` 1.4.0: добавлено самообновление.

## [0.7.0] — 2026-10-09

### DN1Sup Extension Store (v0.7.0)
- **Статус «Смена версии» для релизов новее по дате, но ниже по номеру**
  (смена схемы нумерации, напр. Time Project 2.4.1 → 0.4.1): раньше такой
  релиз молча показывался как «актуальная версия» и обновление невозможно
  было установить из каталога. Теперь карточка предлагает установку
  (кнопка «Установить», бейдж «Смена версии»), а вкладка «Обновления»
  учитывает и такие релизы.
- Каталог запрашивает **список релизов** репозитория
  (`GET /releases?per_page=20`) вместо только `/releases/latest`: предлагаемый
  релиз выбирается как новейший стабильный (без draft/prerelease) по дате
  публикации — GitHub возвращает «latest» по дате, из-за чего после
  нестандартной публикации «latest» мог оказаться ниже установленной версии.
- Снапшот релизов переведён на формат v2 (списки по репозиториям, до 10
  релизов); старый одиночный формат читается без потерь.
- Чистая логика вынесена в `Dn1sup::Updater` (`releases`, `choose_release`,
  `product_status`) и покрыта тестами, включая живой сценарий
  dn1sup_time_project2 (2.4.1 → 0.4.1).

## [0.6.1] — 2026-10-07

### DN1Sup Extension Store (v0.6.1)
- **Прикладной лог в приложении сделан кратким** (`Sketchup.temp_dir/dn1sup_updater.log`):
  остаются только ключевые события — открытие каталога, результат установки/
  обновления/удаления расширений и ошибки (`[INFO]` / `[ERROR]`).
- **Подробные записи убраны из прикладного лога в dev-режим**: каждая команда UI,
  каждый запрос релиза, отрисовка каталога и ход скачивания теперь пишутся на

  `Sketchup.write_default('Dn1supUpdater', 'debug', true)` (см. README «Dev-режим»).
- Подробная история изменений остаётся в [CHANGELOG.md](CHANGELOG.md) и релизах GitHub.

## [0.6.0] — 2026-10-07

### DN1Sup Extension Store (v0.6.0)
- **Информационное логирование** (`Dn1sup::Updater.log_info`): ключевые события
  каталога теперь видны в ` Sketchup.temp_dir/dn1sup_updater.log` с меткой
  `[INFO]`, ошибки — с меткой `[ERROR]` (ранее в лог попадали только ошибки без
  контекста и without событий Store):
  - открытие каталога, отдача локального снапшота (число продуктов);
  - каждая команда интерфейса (`ready`, `refresh`, `install`, `update`, …);
  - запросы релизов по каждому репозиторию (`latest_release(repo): OK v…` / HTTP-код);
  - сводка опроса (сколько релизов получено), установка/удаление с результатом.
- **Потокобезопасность лога**: запись через Mutex (фоновые потоки + главный).
- `tools/pack.rb` синхронизирует общие файлы из `shared/` и в dev-копию
  `src/dn1sup_ext_manager/` (ранее — только в архив).
- `latest_release(repo)`: в лог пишется запрос по каждому репозиторию
  (`OK v…` / HTTP-код ошибки) — подробности видны в dev-режиме (см. [0.6.1]).

## [0.5.0] — 2026-10-07

### DN1Sup Extension Store (v0.5.0)
- **Интерфейс каталога переписан на Vue 3**: исходники — в `frontend/`
  (Vite + Tailwind + `vite-plugin-singlefile`), сборка одним файлом
  (`npm run build`) кладётся в `src/dn1sup_ext_manager/html/index.html`.
- **Единый мост Ruby ↔ JS**: один экшен-колбэк `call_ruby` (имя команды +
  JSON-параметр) вместо набора отдельных колбэков; состояние и результаты
  операций пушатся в UI через `window.pushState` / `window.pushResult`.
- **Перехват ошибок интерфейса**: JS error hook (`error` /
  `unhandledrejection`) отправляет ошибки в журнал Ruby (`log_js_error`) —
  ошибки Vue/JS видны в `dn1sup_updater.log`.
- **Mock-режим фронтенда**: `npm run dev` в браузере работает без SketchUp
  (мок-данные каталога и операций).

## [0.4.1] — 2026-10-07

### DN1Sup Extension Store (v0.4.1)
- **Исправлена потеря версий и changelog'ов после сетевого сбоя**: неудачный
  запрос релиза больше не кэшируется как `{}` — ранее одна сетевая ошибка
  (OpenTimeout) обнуляла версии и логи изменений в каталоге до конца сессии.
- **Однократный автоповтор** запросов релизов, если сеть была недоступна в

  дата) сохраняются в temp-каталог SketchUp (`dn1sup_ext_releases.json`) и
  отображаются при следующем открытии каталога без сети. Установка/обновление
  всегда делает свежий сетевой запрос.
