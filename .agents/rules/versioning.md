# Правила версионирования проектов и ведения лога изменений

## Модель версий
- **Репозиторий (монорепозиторий / релизы GitHub)**: теги `vMAJOR.MINOR.PATCH` (текущий: `v0.6.0`).
- **Каждое расширение имеет собственную независимую версию** `MAJOR.MINOR.PATCH`:
  - `dn1sup_ext_manager`: `0.3.0`
  - `dn1sup_create_project`: `1.1.0`
  - `dn1sup_time_project2`: `2.4.0`
  - `dn1sup_autoselect_tag`: `0.3.0`
  - `dn1sup_comp_add_view`: `1.3.0`
- **Мелкие фиксы / багфиксы**: увеличивать третью цифру (`PATCH`: `0.1.1`, `0.1.2`, ...).
- **Добавление функционала / редизайн**: увеличивать вторую цифру (`MINOR`: `0.2.0`, `0.3.0`, ...).
- **Первая цифра (`MAJOR`)**: НЕ МЕНЯТЬ пока пользователь явно не скажет ("первую не менять пока не скажу").

## Обязательное ведение лога изменений и версий
- **При любых изменениях в коде любого расширения:**
  1. Изменять соответствующий номер версии расширения:
     - Для `dn1sup_ext_manager`: в лоадере [src/dn1sup_ext_manager.rb](../../src/dn1sup_ext_manager.rb) (`extension.version`) и в [src/dn1sup_ext_manager/main.rb](../../src/dn1sup_ext_manager/main.rb) (`VERSION`).
     - Для внешних расширений: в их рабочих директориях (`main.rb` и loader).
  2. Добавлять пояснения в [CHANGELOG.md](../../CHANGELOG.md) с указанием даты, ID расширения, новой версии и кратким списком изменений.
  3. Пересобирать пакеты и обновлять [registry.json](../../registry.json) через `ruby tools/pack.rb` (скрипт автоматически считывает версии из лоадеров).
  4. Запускать тесты: `ruby test/smoke_test.rb`.
  5. Всегда фиксировать изменения коммитом и отправлять (`git push`) в удалённый репозиторий.
