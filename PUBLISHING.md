# Публикация расширения на GitHub

Требования к репозиторию расширения, при которых **DN1Sup Extension Store**
находит его на GitHub, показывает в каталоге, устанавливает и предлагает
обновления. Механика поиска описана по коду менеджера
([dn1test/dn1sup_ext_manager](https://github.com/dn1test/dn1sup_ext_manager)).

## Как менеджер ищет расширения

- Менеджер перечисляет репозитории аккаунта/организации **`dn1test`**
  (`GET api.github.com/users/dn1test/repos`, при недоступности — `orgs/...`).
  Запрос без пагинации — видны первые 100 репозиториев.
- Кандидат должен: начинаться с **`dn1sup_`** (регистр важен), быть
  **не архивным** и отсутствовать в `registry.json` каталога менеджера.
- Автопоиск выполняется раз в 24 часа и по кнопке «Обновить» в каталоге.
- Найденный репозиторий попадает в каталог, только если у него есть
  **хотя бы один релиз с приложенным `.rbz`** (черновики и prerelease
  менеджер не предлагает к установке).
- Метаданные карточки (id, имя, описание, версия) менеджер берёт из
  `registry.json` в корне ветки `main` самого репозитория; если его нет —
  из описания репозитория на GitHub и имени репозитория.

## Обязательные требования

1. **Имя и место.** Репозиторий называется `dn1sup_<имя>` и лежит в аккаунте
   `dn1test`; репозиторий не в архиве.
2. **`registry.json` в корне ветки `main`** — карточка и авторитетная версия
   (формат ниже).
3. **GitHub Releases, а не просто теги.** Релиз не черновик и не prerelease,
   к нему приложен архив `.rbz` — предлагаемым становится релиз,
   **новейший по дате публикации** (не по номеру версии).
4. **Тег релиза `vMAJOR.MINOR.PATCH`.** Для показа «Что нового» (список
   коммитов) нужны оба тега — установленной и предлагаемой версий
   (`compare/v<installed>...v<offered>`).
5. **Регистратор `<id>.rb` в корне `.rbz`.** После установки он попадает в
   `Plugins/<id>.rb` — по наличию этого файла менеджер понимает, что
   расширение установлено.
6. **`.rbz` приложен к релизу.** Менеджер ищет ассет с именем `<id>.rbz`
   (равенство без учёта регистра); иначе берёт первый `*.rbz` в ассетах.

## registry.json

```json
[
  {
    "id": "dn1sup_<имя>",
    "name": "Человеческое имя",
    "description": "Одно предложение — что делает расширение",
    "repo": "dn1test/dn1sup_<имя>",
    "version": "1.2.3"
  }
]
```

- Допустим и формат `{"extensions": [ ... ]}` — объект с массивом.
- `id` обязан совпадать с именем репозитория и с id, заданным регистратору
  (`SketchupExtension#id=`), — по нему менеджер сопоставляет репозиторий,
  карточку и установленное расширение.
- `version` — текущая версия **без** префикса `v`. Она считается
  авторитетной при проверке обновлений; кроме того, релиз, опубликованный
  позже даты установки, тоже считается обновлением.

## Релизы

- Публикуйте именно **Release** (не только тег): тело релиза — changelog в
  Markdown, менеджер показывает его в карточке. В монорепозитории с
  несколькими расширениями можно оформлять секции `### <id>` — менеджер
  возьмёт секцию нужного расширения.
- Тег — `vMAJOR.MINOR.PATCH`; версия в `registry.json` и регистраторе
  хранится без `v`.
- Смена схемы нумерации версий не ломает обновление: если релиз новее по
  дате, но номер ниже, менеджер предложит статус «switch» вместо «update».

## Регистратор внутри .rbz

```ruby
require 'sketchup.rb'
require 'extensions.rb'

module Dn1sup
  module MyExt
    unless file_loaded?(__FILE__)
      ext = SketchupExtension.new('dn1sup_my_ext', File.join('dn1sup_my_ext', 'main'))
      ext.description = 'Что делает расширение'
      ext.version     = '1.2.3'
      ext.creator     = 'DN1Sup'
      ext.id          = 'dn1sup_my_ext' if ext.respond_to?(:id=)
      Sketchup.register_extension(ext, true)
      file_loaded(__FILE__)
    end
  end
end
```

- Регистратор — единственный файл `.rb` в корне архива, названный `<id>.rb`.
- `ext.id = '<id>'` обязателен: без него менеджер не сопоставит
  установленное расширение с записью каталога и не покажет версию.

## Рекомендуемые практики

- **Описание репозитория** на GitHub — фолбэк для описания карточки, если
  в `registry.json` нет `description`.
- **CI-сборка**: workflow `.github/workflows/release.yml` — по тегу `v*`
  собрать `.rbz` (`ruby tools/pack.rb`) и приложить к релизу. Пример есть
  в любом репозитории `dn1test/dn1sup_*`.
- **`shared/dn1sup_updater.rb`** в составе расширения — даёт пункты меню
  «Проверить обновления» / «Страница релизов на GitHub» без участия
  менеджера.
- **Запись в каталоге** (`registry.json` менеджера) не обязательна:
  автопоиск покажет репозиторий сам с бейджем «Найдено». Запись делает
  карточку «штатной» и позволяет задать имя/описание до первого релиза.

## Чек-лист этого репозитория

| Требование | Статус |
|---|---|
| Имя `dn1sup_*` в аккаунте `dn1test` | ✅ `dn1test/dn1sup_ext_manager` |
| Не archived | ✅ |
| `registry.json` в корне `main` | ✅ (id, name, repo, version) |
| Стабильные релизы с `<id>.rbz` | ✅ `packages/dn1sup_ext_manager.rbz` через CI |
| Теги `vMAJOR.MINOR.PATCH` | ✅ (workflow на `v*`) |
| Регистратор `<id>.rb` + `ext.id` | ✅ `src/dn1sup_ext_manager.rb` |

Каноническая копия этого документа живёт здесь, в репозитории менеджера;
в остальных репозиториях `dn1sup_*` лежат синхронизированные копии со своим
чек-листом.
